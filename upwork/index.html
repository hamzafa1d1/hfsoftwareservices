01 · The loop

Speed comes from structure, not from rushing.

Every change runs through the same nine steps. Each step starts in a fresh session and hands the next one a single file. Agents do the research, planning, coding, review and QA. A person decides at two gates.

  1. 01 / 09

    Brainstorm

    Engineers, product and design explore the problem together while research agents fan out. AI is a tool in the room, not the driver.

    Output · brainstorm.md
  2. 02 / 09

    Plan

    A planner agent writes acceptance criteria tied to test fixtures. Design artefacts come first: data model, sequence diagram, API schema, and a decision record for every significant choice.

    Output · plan.md
  3. 03 / 09

    Approve Human gate

    A person approves the plan and it freezes. Changing it later is an explicit, logged replan, never a silent edit. Freeze is enforced in the AI tools, a pre-commit hook and CI.

    Output · frozen plan
  4. 04 / 09

    Build

    A fresh coder agent builds one milestone at a time against the frozen plan, under binding rules for money, tenants, the calculation engine and the database.

    Output · code + dev record per milestone
  5. 05 / 09

    Review

    A read-only reviewer returns PASS, CONCERNS or FAIL against the plan. Security, reliability and database lenses are mandatory where the risk is. Any concern goes back to Build.

    Output · review verdicts
  6. 06 / 09

    QA

    A separate QA agent, never the one that wrote the code, runs the verify gate and replays the acceptance criteria.

    Output · evidence.md
  7. 07 / 09

    Ship

    Coder, reviewer and QA run as isolated sub-agents, then the pull request opens with a short plain-language body, screenshots and evidence attached.

    Output · pull request
  8. 08 / 09

    Human review Human gate

    Named reviewers approve, CI goes green, and only then does it merge and deploy. No silent merges.

    Output · merged, deployed to staging
  9. 09 / 09

    Retro

    A redacted digest of the session turns friction into proposed changes to skills and agents. A person approves them. Fix the skill, not the output.

    Output · LEARNINGS.md

Why it holds

Rules for money and tenants

Exact decimals with named rounding. No hand-written tenant filters. A calculation engine with no database or web framework, so it can be tested alone. Schema changes reviewed against real past failures.

Independence by tooling

Reviewers get read and run access only. CI caught a one-word edit that would have given a reviewer write access while the build stayed green. Now it blocks it.

No false green

A fresh install once printed “All checks passed” with 29 unresolved placeholders. Fixed: 76 of 76 adoption checks pass, and all six CI checks pass on Windows too.

The harness kit. I didn’t invent the loop. It started as a team pilot. I wrote it down, added binding rules for payroll-grade data, and packaged it so any repo gets it on day one.

  • 1 install command
  • 5 AI coding tools
  • Plan freeze in tools, hook and CI
  • Approved after external review

Honest limits: the CI gate is advisory until branch protection is switched on. Speed and defect-rate gains haven’t been measured yet.

03 · Work

Real problems, run through the loop.

Four chapters from a US HR SaaS platform that holds pay data for around 115 customer organisations. Client work is anonymised.

Loop · Brainstorm → ReviewPerformance · production diagnosis

Requests up to 217 seconds. Four root causes, not one.

Problem

Managers reported crashes on save and blank screens. Two days of production logs (8,512 requests) showed 69 requests over 60 seconds and a review screen averaging 12.4 seconds.

What I did

Read-only investigation in production. Found four stacked causes: missing indexes, a memory-capped 32-bit app pool, an idle timeout causing cold starts, and an outdated database compatibility level. Added indexes, then re-keyed them when an audit showed they targeted the wrong column.

Loop · Plan → ShipProduct feature · end to end

Pricing every job title against the market, in one go.

What shipped

Bulk salary benchmarking. It groups a company’s job titles, matches each against market data in the background, then estimates a P10–P90 salary range. Admins review, approve, export and refresh, with location variants and per-title overrides.

The fix that followed

About a third of titles returned no salary data, and the “confidence” score was really just the position in a search list. I moved matching to the provider’s real title-matching API, so confidence became an actual score.

Loop · Ship → RetroNight shift · incidents into prevention

Problems used to be found by customers. Now they’re caught by checks.

Health monitoring

A read-only health scan on the production server posts compact alerts to the team’s Slack. It runs every 15 minutes across 16 signals. Before it, incidents arrived as customer complaints.

Single sign-on outage

When an upstream signing certificate changed, I restored sign-in for the 8 affected customer organisations, wrote a rollover runbook, then added expiry and mismatch alerts against each tenant’s live metadata. An expiry-only check would have missed this outage.
