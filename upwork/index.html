How a change reaches production

  1. Brainstorm

    Engineers, product and design explore the problem together while research agents fan out. AI is a tool in the room, not the driver.

    Leaves behind brainstorm.md

  2. Plan

    A planner agent writes acceptance criteria tied to test fixtures. Data model, sequence diagram, API schema and a decision record come before any code.

    Leaves behind plan.md

  3. Approve

    A person approves the plan and it freezes. Changing it later is an explicit, logged replan. The freeze is enforced in the AI tools, a pre-commit hook and CI.

    Human gate. The plan is now read-only

  4. Build

    A fresh coder agent builds one milestone at a time against the frozen plan, under binding rules for money, tenants, the calculation engine and the database.

    Leaves behind code and a dev record

  5. Review

    A read-only reviewer returns pass, concerns or fail against the plan. Security, reliability and database lenses are mandatory where the risk is. Concerns go back to Build.

    Reviewers can read and run code, never change it

  6. QA

    A separate QA agent, never the one that wrote the code, runs the verify gate and replays the acceptance criteria.

    Leaves behind evidence.md

  7. Ship

    Coder, reviewer and QA run as isolated sub-agents, then the pull request opens with a short plain-language body, screenshots and evidence.

    Opens the pull request

  8. Human review

    Named reviewers approve, CI goes green, and only then does it merge and deploy. No silent merges.

    Human gate. Merged and deployed to staging

  9. Retro

    A redacted digest of the session turns friction into proposed changes to skills and agents. A person approves them. Fix the skill, not the output.

    Leaves behind LEARNINGS.md

I didn’t invent the loop.I made it installable.

It started as a team pilot. I wrote it down, added binding rules for payroll-grade data, and packaged it as a kit that installs with one command in five AI coding tools. The plan freeze is enforced in the tools, a pre-commit hook and CI.

Independence is enforced by tooling, not by promise. CI caught a one-word edit that would have given a reviewer write access while the build stayed green, and now blocks it. A fresh install once printed “All checks passed” with 29 unresolved placeholders. Today 76 of 76 adoption checks pass.

Still to do: the CI gate is advisory until branch protection is switched on, and the speed and defect-rate gains haven’t been measured yet.

How do we start?

Email me what’s slow, fragile or stuck. We have a short call, then I send you a written plan with acceptance criteria and a fixed scope. You approve it before any code is written.

What does it cost?

A fixed price for the scope you approve, agreed after the first call, so there are no surprises mid-project.

Who owns the code?

You do. Everything goes into your repository, with the tests, the evidence and the runbooks your team needs to run it without me.

How do you check code that AI agents wrote?

Agents never approve their own work. The plan is frozen before coding, a read-only reviewer and a separate QA agent check every change, and a person reviews it before it merges. The evidence is attached to every pull request, so you can read it yourself.
