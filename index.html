03 — Case studies

Four systems, still running.

Case 01 · US HR SaaS platform · 2026

Legacy compensation review screen: from 20-minute timeouts to about 20 seconds

Problem
The worst approver view took up to 20 minutes, timed out and could crash on save. Nobody had measured where the time went.
What shipped
Read-only production diagnosis and controlled benchmarks, then query indexes, request-scoped formula memoization, deferred detail rendering and Playwright characterization tests around the old behaviour.
Measured result
Worst view completes in about 20 seconds · a representative query fell from 7,845 to 4 logical reads
Stack
ASP.NET / VB.NET · SQL Server · Playwright · AWS · IIS

Case 02 · US HR SaaS platform · 2026

AI-assisted delivery with quality gates: ticket to verified production fix, one engineer

Problem
One engineer owning a legacy module needed investigation, delivery and verification that could be repeated safely, fast.
What shipped
An eight-stage workflow — gather, explore, plan, code, test, review, cleanup, ship — with 10+ repository-specific skills, subagents and safety hooks, portable across Claude Code, Copilot, Cursor and Codex. Scheduled PR review during work hours and a read-only production health scan.
Measured result
Used for production hotfixes with automated suites and live verification · health scan across 16 signals every 15 minutes
Stack
Claude Code · MCP · GitHub Actions · Playwright · PowerShell · Slack

Case 03 · Corporate-card fintech · 2024–2025

LLM-assisted fraud review on Mastercard corporate spend: 10,000+ transactions a day, manual reviews halved

Problem
Suspicious card transactions were reviewed by hand, and fraud surfaced late or not at all.
What shipped
Multi-layer LLM analysis in front of the review queue, a .NET backend and an Angular review interface for the finance team.
Measured result
10,000+ transactions screened a day · manual reviews halved · €3,000+ in fraudulent charges recovered during the pilot
Stack
.NET · Angular · Azure · SQL Server · LLM pipeline

Case 04 · Corporate-card fintech · 2023–2025

07 — FAQ

The six things people ask.

01Who owns the code?

You do. Work lands in your repository, under your account, from the first commit. No licence, no hosted black box, no dependency on me to run it.

02What happens if you're unavailable?

Every engagement names a backup engineer who has access and context, and handoff docs are kept current in your repo rather than written at the end. Contracts are milestone-based, so you are never paying ahead of delivered work.

03How do you measure whether the agent works?

An eval suite with cases drawn from your real data, thresholds agreed before the build, and a regression gate in CI that blocks a release when quality drops. After launch, a dashboard tracks the same numbers and alerts on drift.

04What does it cost?

Fixed-price sprints and monthly retainers, quoted after the audit call so the number is attached to a defined scope. The audit itself is free.

05Which stack and models do you use?

.NET/C# and TypeScript/Node, React or Angular on the front, SQL Server and PostgreSQL, AWS and Azure with Terraform. Models sit behind an interface so you can change provider without rewriting the workflow.

06Do you work through Upwork or direct?

Either. Upwork gives you escrow and milestone protection; direct gives you an MSA with a registered Tunisian SUARL that exports services and invoices cleanly.
